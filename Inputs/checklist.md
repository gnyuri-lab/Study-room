# Чек-лист проверки приложения «Study room / Учебный кабинет»

**Версия:** 1.0 · **Дата:** 27.09.2026
**Как пользоваться:** отмечать `[ ]` → `[x]` по мере проверки. Колонка «Ожидаемый результат» — эталон, с которым сверяется фактическое поведение. При расхождении — записать в раздел 15.

**Учётные данные для проверки**
- Администратор при первом входе: `admin@admin.com` / `1234` (далее — собственные логин и пароль, введённые при первой смене)
- Студенты и куратор: пароль — первый выход в рамках проверки раздела 5
- Реестры из папки `Inputs` зафиксированы 27.09.2026: `Список студентов-ФК_11.xlsx` корректен целиком, в `Список студентов-ФК_21.xlsx` отбраковываются строки 5 и 6
- Демо-студенты демо-курса — вымышленные персоны, создаются скриптом; не совпадают с реестрами из папки `Inputs`

---

## 1. Первый вход администратора

- [ ] Вход по `admin@admin.com` и паролю `1234` выполняется
- [ ] Приложение **не пускает** в рабочие экраны до смены учётных данных
- [ ] Требуется изменить **и логин, и пароль**, подтверждение обязательно
- [ ] Новый пароль короче **8 символов** отклоняется с понятным сообщением
- [ ] Новый пароль ровно из 8 символов принимается
- [ ] Логин, уже занятый другим пользователем, отклоняется
- [ ] После смены учётных данных вход по новым логину и паролю работает
- [ ] Вход по старым `admin@admin.com` / `1234` больше не работает
- [ ] Открываются кнопки «Создать курс» и «Редактировать курс / группы студентов»

## 2. Создание курса и заданий

- [ ] Форма курса: поля названия, описания, добавления задания
- [ ] Описание задания вводится вручную
- [ ] Описание задания импортируется из файла
- [ ] К заданию прикрепляется файл (материалы лекций, шаблон `.xlsx`)
- [ ] Прикреплённый файл скачивается администратором и открывается
- [ ] Кнопка «Сохранить» открывает **предварительный просмотр** формы
- [ ] После подтверждения данные сохранены и видны на экранах пользователей
- [ ] Администратор выходит и входит по новым учётным данным — курс на месте
- [ ] Дедлайн задания задаётся вручную; рядом с полем видна подсказка со сроком из описания ДЗ
- [ ] Дедлайн отображается у студента и куратора корректно; в списках, карточках студента и куратора и на предпросмотре задания надпись «Дедлайн» и дата — красным, «не задан» — приглушённым
- [ ] Задание без дедлайна не ломает расчёты прогресса

## 3. Редактирование и удаление курса

- [ ] В «Редактировать курс» доступны: изменить курс, удалить курс, добавить группу, изменить группу
- [ ] «Изменить курс» открывает заполненную форму, каждое поле редактируется
- [ ] В курс добавляется новое задание
- [ ] «Удалить курс» показывает перечень того, что будет удалено, и требует подтверждения
- [ ] После подтверждения удалены курс, задания, файлы, группы, сдачи
- [ ] В журнале действий осталась запись об удалении курса

## 4. Добавление и изменение группы (CRUD)

- [ ] Группа создаётся вручную
- [ ] Студент добавляется в группу: ФИО, роль, e-mail, пароль
- [ ] Пароль короче **5 символов** отклоняется
- [ ] Пароль ровно из 5 символов принимается
- [ ] Некорректный e-mail (без `@` или без домена) отклоняется
- [ ] Запись редактируется: изменённые корректные поля сохраняются
- [ ] Некорректное изменение не сохраняется, показывается причина
- [ ] Удаление записи из группы работает, если группа опустела
- [ ] **Удаление группы с непустым составом блокируется** с объяснением

## 5. Учётные записи: пароли и доступ

- [ ] Администратор **видит пароль** студента и куратора в карточке или списке
- [ ] Администратор может **выдать пароль повторно** (сгенерировать новый)
- [ ] Действие повторной выдачи попало в журнал аудита
- [ ] Куратор **не видит** паролей ни своих, ни чужих
- [ ] Студент **не видит** паролей ни своих, ни чужих
- [ ] Студент может сменить свой пароль в профиле
- [ ] Куратор может сменить свой пароль в профиле
- [ ] При смене пароля требуется подтверждение старого
- [ ] Смена пароля попадает в журнал аудита
- [ ] **Один и тот же e-mail может завести счета на двух разных курсах** — оба работают
- [ ] При входе по e-mail, присутствующему на двух курсах, предлагается **выбор курса**
- [ ] **В пределах одного курса** повторный e-mail отклоняется с объяснением

## 6. Импорт списка из файла

### 6.1 Механика

- [ ] Загрузка файла `.xlsx` и `.csv` работает
- [ ] До подтверждения **ничего не записывается** в базу
- [ ] Показан предпросмотр с вердиктом по каждой строке
- [ ] Указано количество корректных строк из общего числа
- [ ] Указаны номера строк с ошибками
- [ ] Указана **суть ошибки** по каждой неверной строке
- [ ] После подтверждения сохранены **только корректные** строки
- [ ] Отчёт об импорте сохраняется в журнале аудита
- [ ] Повторный импорт того же файла не создаёт дублей
- [ ] Файл, у которого пароли заданы формулой, читается корректно

- [ ] Строка с e-mail **без `@`** отклоняется
- [ ] Строка с e-mail **без домена** (`ivanov@`) отклоняется
- [ ] Строка с пустым ФИО отклоняется
- [ ] Строка с ролью, отличной от «студент» и «куратор», отклоняется
- [ ] Строка с паролем короче 5 символов отклоняется

- [ ] Файл `.csv` с теми же данными обрабатывается так же, как `.xlsx`
- [ ] Файл, у которого пароли заданы **формулой без кэшированного значения**, всё равно читается

## 7. Студент

- [ ] Вход по e-mail и выданному паролю
- [ ] «Мои курсы»: виден только курс, в котором состоит студент
- [ ] По каждому курсу показан прогресс по статусам
- [ ] «Мои задания» по курсу: название, описание, **дедлайн**, статус
- [ ] Материалы задания скачиваются
- [ ] Сдача работы: файл + комментарий отправляются
- [ ] После сдачи статус становится «на проверке»
- [ ] Студент **не видит** чужих работ и чужих списков
- [ ] При попытке открыть чужое задание или чужой курс — отказ

## 8. Пересдача и лимит попыток

- [ ] Сдача из статуса «на проверке» **запрещена** (нужна обратная связь куратора)
- [ ] Куратор ставит «на доработку» с комментарием → студент может пересдать
- [ ] Повторная сдача увеличивает номер попытки
- [ ] История всех попыток видна в карточке задания
- [ ] После **третьей** попытки кнопка сдачи блокируется с объяснением
- [ ] Из статусов «сдано» и «сдано после дедлайна» сдача невозможна

## 9. Куратор

- [ ] Вход по e-mail и выданному паролю
- [ ] Видны **только** те курсы и группы, к которым прикреплён куратор
- [ ] Таблица успеваемости: ФИО, группа, дедлайн, статус; **дата дедлайна красным**, «не задан» — приглушённым
- [ ] В таблице **нет** столбцов e-mail и пароль
- [ ] Куратор открывает файл работы, скачивает вложение
- [ ] Ставит статус «сдано» с комментарием
- [ ] Ставит статус «на доработку» с обязательным комментарием
- [ ] Прикрепляет файл к комментарию
- [ ] Куратор **не может** изменить уже принятую работу
- [ ] Куратор **не может** создавать курсы, группы и задания
- [ ] **Администратор** может вернуть принятую работу в статус «на доработку», действие в аудите

## 10. Статус «сдано после дедлайна» (автоматический)

- [ ] Работа сдана **до** дедлайна, куратор нажал «сдано» → статус **«сдано»**
- [ ] Работа сдана **после** дедлайна, куратор нажал «сдано» → статус **«сдано после дедлайна»**
- [ ] Отдельной кнопки «сдано после дедлайна» у куратора **нет**
- [ ] Статус виден студенту и в таблице куратора
- [ ] Смена статуса записана в журнал аудита с предыдущим и новым значением

## 11. Дашборд и диаграммы

- [ ] Дашборд администратора: основные показатели, таблицы, списки
- [ ] Дашборд куратора: те же элементы, но в рамках своих групп
- [ ] Диаграммы по статусам отражают реальные числа
- [ ] Фильтры работают: курс, группа, задание, поиск по имени студента (подстрока, без учёта регистра); при вводе букв показывается список полных ФИО области видимости, значение выбирается из списка
- [ ] Фильтры комбинируются
- [ ] Смена фильтра не сбрасывает остальные
- [ ] Диаграммы рисуются без внешних сервисов, страница работает офлайн

## 12. Архив и сохранность работ

- [ ] Задание **со сдачами** удаляется только в архив — работы не пропадают
- [ ] Архивное задание не отображается у студента как активное, но его история доступна администратору
- [ ] Задание **без сдач** удаляется полностью
- [ ] Группа **со сдачами** удаляется только в архив
- [ ] **Удаление курса** удаляет всё каскадом, с подтверждением и перечислением
- [ ] Записи журнала аудита после удаления курса сохраняются
- [ ] В журнале аудита удалённого автора — обезличенная запись

## 13. Вложения

- [ ] Файл недопустимого типа отклоняется с пояснением
- [ ] Файл больше 10 МБ отклоняется с пояснением
- [ ] Больше 5 файлов на сдачу отклоняется
- [ ] Больше 5 файлов на задание отклоняется
- [ ] Скачивание файла недоступно пользователю без прав на него
- [ ] Имя файла с пробелами, кириллицей и спецсимволами обрабатывается корректно
- [ ] Подставка пути в имя файла (`../`) не приводит к чтению посторонних файлов

## 14. Аудит, адаптивность, окружение

- [ ] В журнале есть записи: вход, смена учётных данных, CRUD курса, импорт, сдача работы, смена статуса, скачивание файла, повторная выдача пароля
- [ ] Журнал фильтруется по дате, роли, курсу, сущности
- [ ] Журнал выгружается в CSV
- [ ] В журнале **нет** паролей в открытом виде
- [ ] В журнале **нет** IP-адресов
- [ ] Интерфейс корректен на ширине 360 px, без горизонтальной прокрутки
- [ ] Работает в Chrome, Edge, Safari и Яндекс.Браузере
- [ ] В репозитории нет токенов, паролей и ключей
- [ ] Приложение запускается локально без доступа в интернет
