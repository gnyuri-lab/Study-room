# Отчёт по проекту «Учебный кабинет (Study room)»

**Коротко:** локальный веб-сервис для курсов: администратор собирает курс и группы, студенты сдают работы, кураторы проверяют, руководитель смотрит ведомость. Работает на одной машине, без интернета и облаков.
**Итог:** 72 FR / 38 BR / 47 AC / 14 NFR, 691 автотест, этапы Э-0…Э-11, версия 0.11.1 (`ver:4`).

---

## 1. Проблема и аудитория

**Проблема.** Небольшое подразделение (кафедра, школа, курс) ведёт учебный процесс вручную: реестры в Excel, сдача работ в почте/мессенджерах, статусы и ведомость считаются вручную, история проверки теряется, доступы разбросаны по файлам. Облачные LMS не годятся: по требованиям данные не должны покидать машину, а внешние сервисы и API запрещены.

**Аудитория.**

| Роль | Кто | Задача |
|---|---|---|
| Администратор | сотрудник, ведущий курс | курс, группы, импорт реестра, доступы, надзор |
| Куратор | проверяющий группы | работы, обратная связь, статусы |
| Студент | обучающийся | задания, сдача, пересдача, статусы |

Контекст: закрытая локальная сеть, одна машина, десятки пользователей, учебные/вымышленные данные.

## 2. Выбранный MVP

Минимальный продукт — **полный цикл одного задания**, а не все функции сразу: курс → группа → задание → сдача → проверка → статус → ведомость.

- **Стек (жёстко по ТЗ):** Python 3.12+ · Flask 3 · Jinja2 · SQLite · ванильный JS; ровно 5 зависимостей, без ORM, SPA, Docker, CDN и внешних вызовов.
- **В объёме MVP:** три роли и их права; курсы/задания/группы; импорт реестров с предпросмотром; сдача файлов с лимитами; пересдача (3 попытки); статусы, включая «сдано после дедлайна» (вычисляется системой); дашборды с фильтрами; ведомость XLSX; журнал действий; резервные копии; показ/сброс паролей администратором.
- **Сознательно вне MVP (22 пункта §4.2):** поиск, сортировка, пагинация, уведомления, чат, баллы, антиплагиат, PDF, мобильное приложение, внешние AI/API и др.

## 3. Что реализовано

Разработка шла этапами Э-0…Э-11, каждый закрывал согласованный блок требований:

- **Учёт и доступ:** вход, выбор курса при одном e-mail на двух курсах, обязательная смена учётных данных администратором, 403 для чужих ролей, сброс корзины фильтров при повторном входе.
- **Курсы и группы:** создание/редактирование/удаление (каскад с подтверждением по названию), архивирование при наличии сдач, CRUD групп и участников.
- **Импорт реестров:** предпросмотр с вердиктом на каждую строку, в БД пишутся только корректные строки, отчёт с номерами и причинами ошибок; чтение формулы-пароля из эталонных файлов.
- **Задания и сдачи:** материалы, дедлайны, до 5 файлов × 10 МБ с проверкой типа по расширению и содержимому, лимит попыток, блокировка до обратной связи.
- **Проверка:** комментарии с файлами от обеих сторон, статусы «сдано»/«на доработка», терминальные статусы — только администратор.
- **Аналитика:** дашборд администратора/куратора с фильтрами (курс → группа → задание → студент), SVG-графики своего кода, выгрузка ведомости (сводка/разрезы/ведомость).
- **Надёжность:** миграции SQL, резервные копии JSON с предпросмотром восстановления, журнал действий без IP, пароли = хеш (pbkdf2) + обратимое шифрование (админ видит пароль — требование FR-09).
- **Документация:** ТЗ (72 FR / 38 BR / 47 AC / 14 NFR), чек-лист приёмки на 143 пункта, README для заказчика, история этапов.

## 5. Что улучшишь дальше

Всё — только по согласованию с ТЗ (новые требования = новые FR/BR/AC в одном изменении):

1. **Комфорт работы со списками** — поиск, сортировка, пагинация (сейчас вне объёма §4.2; первые кандидаты при расширении).
2. **Уведомления внутри приложения** — «новая обратная связь», «работа возвращена» (без внешней почты — она запрещена NFR-03).
3. **Безопасность развёртывания** — HTTPS и запуск как службы Windows, если пилот выходит на несколько машин.
4. **Экспорт** — PDF-версия ведомости, кастомные столбцы.
5. **Инфраструктура** — CI (pytest на каждый коммит), типизация (mypy), нагрузочные тесты на 100+ одновременных.
6. **Сопровождение** — регулярный авто-бэкап по расписанию, ротация учётных данных и секретов, руководство администратора (сейчас — README и журнал).
7. **Масштабирование** — при переходе за пределы одной машины: PostgreSQL и выделенный сервер (сейчас SQLite — осознанное ограничение пилота).
